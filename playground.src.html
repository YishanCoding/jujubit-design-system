设计思路

?

本节 F 指设计团队 Figma 与设计周报；新版指本规范已记录的 2026-10 线上实测。

改版需求用于理解创作路径；未明说的理由单独标推断，不代表已验证的转化效果。

用作品说明能做什么，用清晰入口引导定制；推断项待设计确认。

网站设计思路

  • 橙色突出主操作，黑白承载内容。F
    ?

    做：主按钮用品牌橙，文字与底色用中性色。不做：给每个入口分配一种强调色。

    推断 让用户先看到作品，再找到开始定制的入口，减少装饰色争抢注意力。

    用法：沿用色彩与按钮示例。

  • Bebas 标题建立层级，Outfit 正文解释内容。F
    ?

    做：英文标题用 Bebas Neue；正文、按钮、表单用 Outfit。不做：把整段说明排成大写展示字，或再加装饰字体。

    推断 标题帮助扫读，正文保证细节可读；两者分工比每块换字体更容易保持品牌识别。

    用法：从字体阶梯选层级。

  • 先展示作品和实物效果，再解释创作方法。F
    ?

    设计稿把作品、模板与过程展示放在主要位置。首页改版需求也要求用产品效果帮助理解定制。

    做：首屏给清晰作品和创作入口，分类图展示产品效果。不做：只用抽象装饰图，让用户猜能做出什么。

    用法：参考模板入口与步骤区块。

  • 按「看作品 → 选风格 → 了解过程与实物 → 开始定制」组织信息。推断
    ?

    这是根据首页改版需求整理的信息顺序，用户可跳过说明直接定制。

    做：首屏说明能做什么并保留创作入口；模板帮助选择；步骤、实物与 FAQ 回答顾虑。已有想法的人可直接开始。

    不做：把所有卖点挤进首屏，或要求用户看完说明才能定制。

  • 商品图按实际类型标注，AI 预览、产品渲染与实物照分开。推断
    ?

    图片用途不能证明图片来源；“商品图”也可能是渲染图。分开标注，才能让用户判断哪些展示创意，哪些证明交付效果。

    做：在图旁写明原始照片、AI 预览、产品渲染或实物照片；对比图使用同一作品、已获授权的素材。

    不做：把 AI 预览标成实物或买家秀。来源不明时只标 Sample image，不作交付证明。

  • 桌面多列比较，手机减少同屏信息并保留定制入口。新版
    ?

    现有商品网格桌面四列、手机两列；区块标题从 64 缩为 28。沿用布局与商品卡的响应式规则。

    推断 桌面留出比较空间；手机优先看清主体和操作。做：分别选取适合两端的图片裁切。不做：把桌面整页等比缩小，或把必要信息藏在悬停里。

  • 语气围绕创作的好奇与成就感，操作说明保持直接。推断
    ?

    这是从品牌人物和现有素材归纳的建议；品牌调性原文未取得，尚非正式语气规范。

    做：写清用户可以创作什么、下一步做什么。不做：用夸张承诺替代产品说明，或把每次创作都写成煽情故事。

新版 UI 风格的设计思路 · 2026-10

  • 首页区块改为全宽铺满，只留左右边距。新版
    ?

    变化：旧稿的居中窄容器改为全宽区块。

    推断 想解决：宽屏两侧空白过多，作品展示面积不足。

    用法：首页展示区用 .jjb-container.jjb-container--wide。做：保留桌面与手机各自的 gutter。不做：把文章、政策和表单也强行铺满。

  • 区块标题统一为居中 Bebas 64，右侧放 View All。新版
    ?

    变化：新版统一标题与入口组合；旧站已有居中标题，不把居中本身算作新创。

    推断 想解决：区块间标题层级与查看更多入口不一致。

    用法：复制 .jjb-section-head，手机沿用 28 的标题 token。做：有集合页时配右侧 View All。不做：为单个区块另造标题样式，或放无目标的链接。

  • 网格间距从旧稿的 30 收到 12。新版
    ?

    变化：商品、分类和信任卡网格采用更紧凑的间距。

    推断 想解决：卡片间空白割裂作品，降低同屏比较效率。

    用法：沿用 var(--jjb-grid-gap)。做：收紧卡片之间的距离。不做：连区块间距和正文留白一起压缩。

  • 首屏用透明玻璃导航，滚动后切回白底。新版
    ?

    变化：首屏导航叠在主视觉上，与滚动后的白底导航区分。

    推断 想解决：不透明顶栏切断主视觉，同时保证滚动后的菜单可读。

    用法：首屏使用 .jjb-nav--glass，滚动状态参考导航示例。做：逐张检查背景上的文字对比。不做：在浅色内容页永久套透明白字导航。

  • 筛选胶囊替代下划线 tab。新版
    ?

    变化：旧稿的 Bebas 下划线 tab 改为黑白胶囊，选中态用黑底白字。

    推断 想解决：筛选项看起来像标题，点击范围和当前选项不够明确。

    用法：复用 .jjb-chip 及其状态属性。做：筛选按钮同步 aria-pressed。不做：仅用文字下划线表示选中。

  • 商品卡去掉品牌副标和 Quick view，悬停换第二张图。新版
    ?

    变化：旧稿的品牌副标与悬浮 Quick view 按钮移除；可用第二张图补充角度。

    推断 想解决：重复信息和浮动按钮遮挡作品，分散进入详情的注意力。

    用法：复制 .jjb-card。做：保留图片、名称、价格和详情链接，第二张图只作补充。不做：把尺寸、材质等必要信息只放在悬停图里。

  • 卡片和 Logo 不加阴影，延续平面表达。新版 F
    ?

    变化边界：新版卡片保持无投影；Logo 禁止加阴影是既有品牌规则，此次继续沿用。

    推断 想解决：界面装饰与作品本身的立体感争抢注意力。

    用法：做：沿用现有卡片底色、边框和留白。不做：给卡片或 Logo 添加悬浮投影。导航、浮层的专用阴影不扩用到卡片。

  • 社媒视频独立成深色区块。新版
    ?

    变化：新版用深灰底承载竖版视频，居中的视频放大，与浅底商品网格区分。

    推断 想解决：连续商品网格节奏单一，让用户能切换到观看作品过程与实物展示。

    用法：参考 .jjb-social，底色沿用 var(--jjb-surface-dark)。做：配清晰封面并保留素材来源身份。不做：把所有内容区都改成深色，或把品牌视频冒充客户评价。

新版
?

JuJu 是品牌角色，负责品牌识别；Maya 和 Danny 代表"用 JuJuBit 创作的人"，负责示范和带入。

两人是 AI 生成的虚构角色，对外不得说成真实客户。气质：好奇、调皮、对自己的作品有点得意——潮玩和创作感，不是贺卡式煽情。

需要真人时只用 Maya 和 Danny 两位固定代言人，不另找新面孔。

动效

线上
?

曲线 cubic-bezier(.165,.84,.44,1)。Figma 没有 motion token，Web 沿用线上实测值；App 动效以设计团队交付的视频为准（下方）。

一条缓动曲线、四档时长；用户开启"减少动态效果"时全部关掉。

品牌与 App 动效交付视频 App 压缩预览版（720p），原片找设计团队
  • hover / 按下 / 颜色变化 200ms；展开、抽屉、tab 切换 300ms；滚动入场 500ms；首屏 800ms。
  • 不用 ease / ease-in-out；只有循环内容（跑马灯、加载转圈）用 linear。

给 AI 用

?

它会自动读取规则、token、组件和素材。skill 跟着本页自动更新，重新跑一次安装命令就能拿到最新版。

装到 ~/.claude/skills/jujubit-design-system 和 ~/.codex/skills/jujubit-design-system。只装一个：命令末尾加 -s claude 或 -s codex。装完重启 agent。

把本规范装成 agent skill，之后对 agent 说"按 JuJuBit 设计规范做一个 xx 页面"即可。

1. 一键安装（Claude Code + Codex，macOS / Linux）
curl -fsSL https://playverseai.com/design/install.sh | bash
2. 手动下载
下载 skill 包（zip） 查看 SKILL.md

解压后把 jujubit-design-system 文件夹放进 agent 的 skills 目录。包里带 tokens.css、components.css、字体、Logo 和图标，离线也能用。

3. 不装 skill，直接给 agent 这段话
按 JuJuBit 设计规范做这个页面。先读 https://playverseai.com/design/skill/jujubit-design-system/SKILL.md ，页面引用 https://playverseai.com/design/tokens.css 和 https://playverseai.com/design/components.css ，组件 markup 从 https://playverseai.com/design/ 复制，不要新增色值、字号、圆角。
修改规范

源文件在 github.com/YishanCoding/jujubit-design-system。改动 push 到 main 后自动构建，约 5 分钟后本页和 skill 包更新。
